# HMCL 公告协议 v1

本文定义 HMCL 公告系统的第一版协议和客户端行为，作为实现与验收依据。
公告源是公开的静态 JSON 文件，由网站发布流程更新，客户端通过 HTTP 定期获取。

## 公告源

约定地址为 `https://hmcl.glavo.site/announcements/v1.json` ，上线时需在文档网站部署该文件。
该地址的部署不由本文完成。协议不兼容的变更使用新地址，旧客户端继续读取原地址。

响应正文是 UTF-8 JSON 数组，表示当前发布的完整公告集合，不分页、不按用户筛选。
空数组 `[]` 表示当前没有公告。公告从集合中删除后，客户端在下一次成功更新时撤回它。
发布文件必须是标准 JSON，不允许注释、重复对象键或重复公告 ID。

发布文件由 [JSON Schema](schemas/announcements/1.0.0.json) 校验，校验器须启用 `format` 检查。
Schema 校验通过后，仍须检查 ID 唯一性、父子引用、语言标签、Markdown 正文和 URL 的语义约束。
客户端采用相同的字段结构约束，但对 URL 字符串采用下文规定的容错行为。

```json
[
  {
    "id": "019976a8-04af-7442-9ffd-ebdaf9bbf68e",
    "type": "board",
    "priority": 100,
    "severity": "warning",
    "title": {
      "default": "Service disruption",
      "en": "Service disruption"
    },
    "content": "**Account sign-in may be temporarily unavailable.**\n\nPlease try again later.",
    "url": "https://example.com/status",
    "expiresAt": "2026-09-13T00:00:00Z"
  },
  {
    "id": "019976b2-ad49-7451-b090-83b66c532cdd",
    "parent": "019976a8-04af-7442-9ffd-ebdaf9bbf68e",
    "type": "board",
    "title": "Workaround",
    "content": "Existing offline sessions are unaffected.",
    "expiresAt": "2026-09-13T00:00:00Z"
  }
]
```

## 公告字段

可选字段通过省略表示未设置，不接受 `null`。

| 字段        | 必填 | 含义                                                                |
|-------------|------|---------------------------------------------------------------------|
| `id`        | 是   | 小写标准文本形式的 UUID v7，永久标识一条公告。                      |
| `type`      | 是   | `board` 为主页公告，`popup` 为弹窗公告。                            |
| `title`     | 是   | 非空本地化纯文本，不解析 Markdown 或 HTML。                         |
| `content`   | 是   | 非空本地化 Markdown 正文，采用下文限定的语法。                      |
| `priority`  | 否   | 有符号 32 位整数，默认为 `0`，越大越靠前。                          |
| `severity`  | 否   | `info`、`warning` 或 `critical`，默认为 `info`，只决定视觉样式。    |
| `parent`    | 否   | 父公告 ID，仅用于主页公告的补充说明。                               |
| `url`       | 否   | 本地化的完整网页链接，用户点击后在系统浏览器打开。                  |
| `expiresAt` | 否   | 失效时刻，格式为 `YYYY-MM-DDTHH:mm:ssZ`；省略表示没有预定失效时间。 |

同一 ID 的正文、标题、链接、优先级、严重程度和失效时间可以更新，但不重置关闭状态。
同一 ID 的 `type` 和 `parent` 不应改变；需要改变展示关系或重新提醒时发布新 ID。
已使用的 ID 不得重新分配给其他公告。客户端不从 UUID 推导有效期或版本号。

`expiresAt` 必须是有效的 UTC 日期时间，秒范围为 `00` 至 `59`。
客户端在当前时间大于或等于该值时隐藏公告，包括已缓存公告和等待展示的弹窗。
时间以客户端系统时钟为准；修改系统时钟会影响失效判断，不承诺离线时获得准确服务端时间。
临时故障公告应设置失效时间；持续故障可以在到期前延长。

本协议不设置定时发布字段。尚未公开的公告应在预定发布时间才加入公开文件。
不包含远程正文加载、版本或平台筛选、已读同步、修订号及历史列表。

## 本地化与正文

本地化字段接受一个字符串，或一个语言标签到字符串的对象。
字符串用于所有语言；对象必须包含非空的 `default` 值，所有值都必须是非空字符串。
语言键使用规范大小写的 BCP 47 标签，例如 `en`、`zh-Hans`、`zh-Hant`；保留键 `default` 用于回退。

客户端使用当前 HMCL 界面语言，通过 `LocaleUtils.getCandidateLocales` 和
`LocalizedText.getText` 按现有候选语言顺序选择文本。标题、正文和链接分别选择，最终回退到 `default`。
发布侧必须提供 `default`，不依赖 JSON 对象成员顺序选择语言。

`content` 固定使用 CommonMark 0.31.2，不自动检测 HTML，也不设置格式选择字段。
支持段落、标题、引用、分隔线、有序和无序列表、强调、行内代码、代码块及链接。
不启用表格、删除线、下划线、任务列表或裸 URL 自动链接等扩展；相关文本按 CommonMark 核心语法解析。
CommonMark 核心语法中的尖括号自动链接仍可使用，但受到下述链接协议限制。
普通换行作为软换行显示为空格；段落之间使用空行，硬换行遵循 CommonMark 规则。
代码块保留文本与换行，不根据语言标记执行代码或启用语法高亮。

原始 HTML 块和行内 HTML 必须转义并显示为普通文本，不解释其中的标签或属性。
图片语法只显示替代文本，不生成图片节点，不请求图片地址；替代文本中的格式标记按其文本内容处理。
发布侧预览必须采用相同规则，不能以 GitHub 页面或其他 Markdown 编辑器的默认渲染作为最终效果。

客户端先按上述规则将 Markdown 转为 HTML，再清理生成结果，最后交给 `HTMLRenderer` 渲染。
生成结果仅保留 `p`、`br`、`em`、`strong`、`code`、`pre`、`blockquote`、`hr`、
`h1` 至 `h6`、`ul`、`ol`、`li` 和 `a` 标签。
仅允许 `a` 的 `href` 属性，以及 `ol` 的 `start` 属性；`start` 必须为 `0` 至 `999999999` 的整数，以保留 CommonMark 有序列表的起始序号。
移除其他属性和不支持的标签；`script`、`style`、`iframe`、`object`、`embed` 连同其内容移除。
其他不支持的标签保留文本内容，意外生成的 `img` 替换为其 `alt` 纯文本。
已转义的 HTML 作为文本保留，不得再次作为 HTML 解析。
清理结果不进入可执行脚本的网页环境。

实现可复用项目现有 CommonMark 依赖，但须使用公告专用的解析和渲染配置：
不启用现有通用转换器的扩展，不使用将缩进代码块作为原始 HTML 输出的模式，并显式处理 HTML 转义与图片替代文本。

`url` 和 Markdown 链接目标必须是含有效主机名、不含用户信息的绝对 HTTPS URL。
无效的正文链接仅显示链接文本，不生成可点击目标；无效的 `url` 不生成详情按钮。
不得把这些链接作为文件路径、命令或自定义协议执行。正文和链接不会在没有用户操作时触发额外资源加载。

## 父子公告与排序

父子关系只支持一层：父公告必须是没有 `parent` 的 `board` 公告，子公告也必须是 `board`。
`popup` 不得声明父公告，也不得作为父公告。子公告必须引用同一列表中的父公告，不允许自引用或循环。
发布时发现无效关系必须拒绝发布。
`popup` 携带 `parent` 属于非法字段组合，客户端拒绝整个响应。
客户端在结构校验后发现缺失父公告、父公告为 `popup`、多级引用、自引用或循环时，隐藏受影响的子公告，其他有效公告继续展示。

根公告按 `priority` 降序排列；优先级相同时按规范小写 ID 的字典序降序排列。
主页公告和弹窗分别排序。子公告紧跟父公告显示，在同一父公告内使用相同排序规则，不参与根公告排序。

公告只有在自身未过期且 ID 不在本地 `closed` 集合中时才具备展示资格。
子公告还要求父公告具备展示资格。关闭父公告仅记录父 ID，但其所有子公告随之隐藏。
单独关闭子公告只记录该子 ID，不影响父公告和其他子公告。
后续事件进展如果需要独立提醒，应发布独立根公告，不使用 `parent`。

## HTTP 获取与缓存

公告文件使用 `Content-Type: application/json`。
托管服务应提供 `ETag`，并建议设置 `Cache-Control: public, max-age=300`。
发布流程应以完整文件替换旧版本；如 CDN 支持，发布和撤回后主动清除对应缓存。

客户端仅在保存了对应的有效正文时发送条件请求：

1. 有 `ETag` 时，原样发送 `If-None-Match`，保留引号及可能存在的 `W/` 前缀。
2. 没有 `ETag`，但有有效 `Last-Modified` 时，原样发送 `If-Modified-Since`。
3. 两者都没有，或者正文丢失、损坏、来自其他源时，发送无条件 GET。

不得从本地请求时间生成 `If-Modified-Since`。
校验器属于整个响应正文，不对应某一条公告，也不代表公告发布时间。

| 结果                                   | 客户端处理                                                     |
|----------------------------------------|----------------------------------------------------------------|
| `200` 且文件有效                       | 原子替换整个公告快照及其校验器；新响应未提供的校验器必须清除。 |
| `304` 且本地有有效快照                 | 保留正文，更新响应提供的校验器；未提供的沿用已有值。           |
| `304` 但没有有效快照                   | 清除孤立的校验器，立即无条件重试一次；再次失败则进入失败退避。 |
| 其他状态、网络失败、解码失败或无效文件 | 保留原快照及校验器，按失败策略重试。                           |

有效文件要求顶层为数组、不超过 100 条公告、解压后的正文不超过 1 MiB，且所有条目满足字段结构约束。
读取时必须执行正文大小限制。重复 JSON 键、重复公告 ID、非法字段类型或非法枚举值会使整个响应无效。
其他 Schema 约束也必须满足，唯一例外是客户端对 `url` 使用本地化文本的结构约束，再对选出的 URL 字符串进行语义检查。
日期必须有效；父子引用错误按前述规则隐藏子公告；Markdown 正文按前述规则转换和清理，URL 字符串按前述规则检查，不因此丢弃其他公告。
无效响应不得部分覆盖旧快照。发布侧校验必须比客户端容错更严格。

客户端忽略未知字段，但未知 `type` 或 `severity` 使响应无效。
以后新增“旧客户端忽略后会错误展示”的字段或枚举值，必须使用新的协议地址。

## 本地状态与刷新

状态文件为 `./.hmcl/announcements.json`，相对 HMCL 工作目录定位。
推荐结构如下，时间戳单位均为 Unix 毫秒：

```json
{
  "cacheVersion": 1,
  "sourceUrl": "https://hmcl.glavo.site/announcements/v1.json",
  "lastAttemptTime": 1788940800000,
  "nextAttemptTime": 1788941442000,
  "failureCount": 0,
  "etag": "\"announcements-42\"",
  "closed": [
    "019976a8-04af-7442-9ffd-ebdaf9bbf68e"
  ],
  "announcements": []
}
```

`announcements` 保存完整响应条目，包括 Markdown 原文和未知字段，不以转换后的 HTML 替换正文；未成功获取过时省略该字段。
空数组是有效快照，不能等同于尚未获取。`etag` 和 `lastModified` 均为可选字符串。
快照与校验器必须一起保存，不能用新响应的校验器标记旧正文。

`closed` 是显式关闭过的 ID 集合，长期保留，不因公告撤回或过期而自动删除。
更换公告源时重置快照、校验器和刷新调度，同时清空属于旧源的关闭记录。
本地文件整体无法解析时，按首次使用处理；关闭记录可能因此丢失。
仅快照校验失败时，保留能够独立校验的关闭记录，清除快照及校验器并重新获取。

客户端启动后先使用有效缓存更新界面，再根据刷新调度异步请求，不阻塞启动和游戏操作。
进程运行期间也按相同调度刷新，不要求重启才取得新公告。客户端同时最多执行一个公告请求。

默认调度参数如下，属于客户端策略，可在后续实现中调优：

- 首次无状态时立即请求；已有状态且未到 `nextAttemptTime` 时等待到期。
- 成功取得有效 `200` 或可用 `304` 后，清零失败次数，下一次请求安排在完成后的 10 分钟加随机 0 至 60 秒。
- 失败后递增失败次数，依次等待 1、2、4、8、10 分钟，此后保持 10 分钟；每次另加随机 0 至 60 秒。
- 发起请求时更新 `lastAttemptTime`，并先保存 1 分钟后的临时 `nextAttemptTime`；完成后用实际调度结果替换。
- 连接超时为 5 秒，单次请求总时限为 15 秒。无条件恢复重试也受相同请求限制。
- 启动时若 `lastAttemptTime` 在未来，或 `nextAttemptTime` 比当前时间晚超过 11 分钟，重置调度并立即刷新。

节流记录不是缓存新鲜度证明，也不改变任何 HTTP 校验器。
CDN 缓存、轮询周期和网络故障都会影响送达与撤回时间，不承诺实时到达。
即使刷新失败，也必须按失效时间及时隐藏缓存公告。

状态写入采用同目录临时文件和原子替换，写入失败时保留旧文件，并继续使用当前进程的内存状态。
同一目录存在多个 HMCL 进程时，使用独立锁文件串行化状态读改写；替换前重新读取并合并 `closed`。
关闭操作只合并关闭记录，不用内存中的旧快照或旧刷新调度覆盖磁盘状态。
网络请求不持有文件锁；提交响应前若磁盘快照及其校验器已被其他进程改变，丢弃本次响应并重新调度，避免覆盖较新的快照。
文件合并仅在相同 `sourceUrl` 下进行。跨进程同时出现同一弹窗不在第一版消重范围内。

## 展示与交互

主页在缓存加载或刷新完成后展示所有具备资格的 `board` 公告。
关闭按钮写入 `closed`，并立即重新计算父子可见性。

`popup` 进入待展示队列，在主界面就绪且没有其他模态操作时依次展示。
运行期间新取得的弹窗采用相同行为；游戏启动等关键操作期间延后展示。
弹出前重新检查最新快照、关闭记录和失效时间，撤回或失效的条目直接移出队列。
同一进程内同一 ID 不得重复入队或同时展示。

确认按钮、窗口关闭按钮和 Escape 均表示关闭该公告并记录 ID；点击正文链接或详情链接不表示关闭。
因退出程序而销毁弹窗不记录关闭。用户主动关闭前，如果公告撤回或到期，关闭弹窗但不写入 `closed`。
同 ID 内容更新不打断当前已打开弹窗，尚未打开的弹窗使用最新内容；下次展示前仍检查关闭状态。
`critical` 不改变这些关闭规则，也不阻止用户继续使用 HMCL。

本地写入失败不恢复当前会话中已关闭的公告，但下一次启动可能再次展示。
关闭状态表示“不再展示”，不定义“已读”或跨设备同步语义。

## 验收场景

实现时至少覆盖以下可观察行为：

1. 首次获取、无公告、离线启动和本地缓存损坏均不阻塞启动器。
2. `200` 更新、`304` 复用及服务器移除校验器时，本地正文与校验器始终匹配。
3. 请求失败之后服务端已有更新，后续请求仍能取得更新，不使用失败时间生成条件请求。
4. 无效 JSON、超限正文、重复 ID 和非法枚举不会覆盖已有快照。
5. 同 ID 修改不重新提醒，新 ID 正常提醒；撤回后恢复同 ID 不丢失关闭记录。
6. 父公告关闭或过期后隐藏子公告；子公告关闭不影响父公告；无效父引用不会阻止其他公告。
7. 缓存公告及待展示弹窗在到期后消失，持续运行时能获取新公告。
8. 所有本地化字段能够按现有候选语言顺序匹配，并稳定回退到 `default`。
9. Markdown 的软换行、硬换行、代码块和有序列表起始序号符合协议；扩展语法不会被作为扩展功能渲染。
10. 多进程更新和关闭并发发生时，不覆盖其他进程新增的关闭记录，不用旧响应覆盖已变更快照。
11. 原始 HTML 显示为普通文本，图片仅显示替代文本；非 HTTPS 链接不可点击，正文无法产生脚本执行、额外资源加载或自定义协议调用。
